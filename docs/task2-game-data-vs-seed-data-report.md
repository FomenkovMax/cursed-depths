# Отчёт: game-data.ts vs seed-data.ts

Задача 2 из TASKS.md. Только анализ, код не менялся.

## Главный вывод

Это не «старый черновик vs новый источник правды». Это **два независимых, не связанных друг с другом слоя данных**, и оба сейчас нужны:

- **`game-data.ts` — единственный источник данных, который реально используется живым геймплеем.** Никакой отдельной БД-таблицы под расы/классы/локации/предметы/врагов/крафт для него нет — все эти массивы читаются в рантайме напрямую.
- **`seed-data.ts` — единственный источник лора (расы/классы/способности), но он никуда не подключён к геймплею.** Пишет в БД (`Race`/`GameClass`/`Ability`/`Location`), но эти таблицы не читает ни один игровой эндпоинт — только новые `/api/races`, `/api/classes`, `/api/abilities`.

Проверено импортами напрямую (`grep` по `src`):

| Экспорт `game-data.ts` | Кто использует |
|---|---|
| `RACES`, `CLASSES` | `api/player/create`, `page.tsx` |
| `LOCATIONS` | `api/locations`, `api/travel`, `api/explore`, `page.tsx` |
| `ENEMIES` | `api/combat/action`, `api/explore`, `page.tsx` |
| `ITEMS` | `api/combat/action`, `api/craft`, `api/quests/claim`, `api/explore`, `page.tsx` |
| `CRAFTING_RECIPES` | `api/craft`, `page.tsx` |
| `ABILITIES` | `api/combat/action`, `page.tsx` |
| `RARITY_COLORS`, `RARITY_NAMES_RU` | `page.tsx` |
| `QUEST_TEMPLATES` | **нигде** (мёртвый экспорт) |
| `getRace`, `getClass`, `getLocation`, `getItem`, `getEnemiesForLocation`, `calculateStat`, `xpForLevel`, `getItemByRarity`, `getAbilitiesForClass` | **нигде** (мёртвые хелперы) |

`seedDatabase()` из `seed-data.ts` вызывается только из `/api/seed` (тот самый незащищённый эндпоинт из Задачи 5).

## Что переносить, что выбрасывать

**Переносить нельзя, потому что это не дубликат — это активные игровые данные:**
- `RACES`, `CLASSES`, `LOCATIONS` (с графом `connections`), `ITEMS`, `ENEMIES`, `CRAFTING_RECIPES`, `ABILITIES`, `RARITY_COLORS`, `RARITY_NAMES_RU` из `game-data.ts` — всё это нужно живому геймплею прямо сейчас. Удалить `game-data.ts` без замены = сломать `/api/combat`, `/api/craft`, `/api/explore`, `/api/travel`, `/api/player/create`, `page.tsx`.
- Расы/классы/способности из `seed-data.ts` — это утверждённый лор проекта (24→26 класса, ~130→158 способностей), его тоже нельзя выбросить.

**Можно выбросить (мёртвый код, ничего не сломается):**
- `QUEST_TEMPLATES` и все 9 хелпер-функций (`getRace`, `getClass`, `getLocation`, `getItem`, `getEnemiesForLocation`, `calculateStat`, `xpForLevel`, `getItemByRarity`, `getAbilitiesForClass`) из `game-data.ts` — нигде не импортируются.

**Не в скоупе Задачи 2, но важно для планирования следующих задач:**
1. `Player`/`CharacterCreation` в схеме хранят расу/класс как обычные строки (`race`, `class`) со значениями из `game-data.ts` (`'human'`, `'warrior'`...). Реальный игровой цикл (создание персонажа, бой, инвентарь) построен вокруг **D&D-системы** из `game-data.ts`, а не вокруг лорной системы из `seed-data.ts`. Подключение `Race`/`GameClass`/`Ability` к живому геймплею (замена `game-data.ts`) — это отдельная, крупная задача смены игровой модели, а не просто "выбросить дубликат".
2. `prisma/seed.ts` (CLI-сидер) сеет таблицу `Enemy` вручную продублированными данными из `game-data.ts.ENEMIES` — но эту таблицу никто не читает (`db.enemy` не встречается в коде вообще). Бой и ислледование берут врагов напрямую из массива `ENEMIES`. Сидер enemies сейчас существует "в вакууме".
3. Найден отдельный баг вне скоупа: `src/app/api/players/route.ts` (во множественном числе, GET/POST) обращается к полям модели `Player`, которых там нет (`raceId`, `classId`, `mana`, `str`...) — похоже на заброшенный черновик другого подхода к схеме. Реальный рабочий эндпоинт создания персонажа — `src/app/api/player/create/route.ts` (в единственном числе), он работает с текущей схемой корректно.

## Неточности в документации проекта

- TASKS.md/CLAUDE.md говорят «24 класса, ~130 способностей» — фактически в `seed-data.ts` **26 классов и 158 способностей**. Не критично, но стоит поправить цифры в документах.

# Мотивированные суждения по списанию задолженности

Два скрипта, каждый со своим входом и своим критерием:

| Скрипт | Вид списания | Вход | Критерий положительного решения |
|---|---|---|---|
| `run_sid.py` | по истечении срока предъявления ИД | реестр .xlsx | с даты окончания ИП прошло **более 3 лет** |
| `run_st46.py` | по ст. 46 ФЗ-229 | реестр .xlsx + папка постановлений | реквизиты сверены, ИП велось **более 2 месяцев**, имущество и доходы отсутствуют |

На выходе — .xlsx с готовым текстом мотивированного суждения по каждой строке.

## Установка и запуск

```bash
pip install -r requirements.txt

# Скрипт 1
python3 run_sid.py реестр.xlsx
python3 run_sid.py реестр.xlsx -o суждения.xlsx --on-date 01.09.2026

# Скрипт 2
python3 run_st46.py реестр.xlsx ./постановления
```

`--on-date` — отчётная дата, на которую считается истечение трёхлетнего срока.
По умолчанию сегодня. Задавайте её явно, если суждения готовятся «на дату».

## Что на входе

**Скрипт 1:** Номер ИД, Номер ИП, Дата окончания, Дата ИД, ФИО Клиента,
Дата рождения клиента, Код кредита, Код Клиента.

**Скрипт 2:** то же + Дата возбуждения ИП, плюс папка с постановлениями об
окончании ИП в формате `.pdf` (с текстовым слоем), `.docx` или `.txt`.
Постановление сопоставляется со строкой реестра по номеру ИП.

Заголовки колонок ищутся по списку синонимов (`COLUMN_SYNONYMS` в
`spisanie/common.py`) — регистр, «№», лишние пробелы значения не имеют.
Если колонка называется совсем иначе, добавьте её название в этот список:
скрипт скажет, какие колонки не нашёл, и перечислит те, что нашёл.

## Что на выходе

Один .xlsx с листами:

- **Сводка** — параметры прогона и статистика по решениям и кодам причин;
- **Реестр решений** — все строки: исходные поля + Решение + Код причины +
  Обоснование + полный текст мотивированного суждения;
- **К списанию**, **Отказ**, **Ручное рассмотрение** — те же строки в разрезе решения.

Решения три, а не два. Третье — **«Ручное рассмотрение»** — принципиально:
строка, которую не удалось проверить (пустая дата, текст вместо даты, дубль в
реестре, нет постановления, скан вместо документа), не превращается в «отказ»
и тем более не проскакивает в списание. Она явно помечается как непроверенная.

## Правила принятия решения

### Скрипт 1

Списание, если `отчётная дата > дата окончания ИП + 3 года`. Строго больше:
ровно в предельную дату срок ещё не истёк.

На ручное рассмотрение уходят: незаполненные обязательные поля, неразбираемые
даты, дубли по паре (Номер ИП, Код кредита), а также аномалии — дата окончания
ИП в будущем, дата ИД позже даты окончания ИП, дата рождения не раньше даты
окончания ИП.

### Скрипт 2

Положительное решение — только если выполнено **всё**:

1. по строке найдено постановление об окончании ИП;
2. совпали ФИО, дата рождения, дата возбуждения и дата окончания ИП;
3. `дата окончания > дата возбуждения + 2 месяца` (строго больше);
4. в постановлении есть ссылка на ст. 46 ФЗ-229, основание — п. 3 или п. 4
   ч. 1 ст. 46, и подтверждено отсутствие имущества и доходов.

Любое невыполненное условие даёт отрицательное решение со списком расхождений
в тексте суждения.

**ФИО сверяется с учётом склонения:** в постановлении должник обычно в
родительном падеже («в отношении Ковалева Петра Сергеевича»), в реестре — в
именительном. Такое совпадение помечается в отчёте примечанием, а не проходит
молча. Известное ограничение: «Иванова» — это одновременно родительный падеж
от «Иванов» и женская фамилия в именительном; без морфологического анализа их
не различить, ошибку перехватывает независимая сверка даты рождения.

**Сканы не распознаются.** PDF без текстового слоя помечается как нечитаемый и
уходит на ручное рассмотрение. Это осознанный выбор: OCR ошибается в цифрах, а
здесь от цифр зависит списание. Если объём сканов большой — это отдельная
задача с отдельной оценкой качества распознавания.

## Тестовые данные и тесты

```bash
python3 make_test_data.py test_data     # сгенерировать вымышленный набор
python3 -m pytest tests/ -q             # прогнать тесты (33 шт.)
```

Данные полностью вымышленные. **Реальные выгрузки с персональными данными в
эту папку класть нельзя** — репозиторий для этого не предназначен.

Набор специально неудобный и включает пограничные и грязные случаи: ровно три
года, три года и один день, ИП ровно два месяца, пустая ячейка, текст вместо
даты, дата числом Excel, дубль с по-разному записанным номером ИП, дата в
будущем, ФИО в родительном падеже, постановление в .docx, скан без текстового
слоя, отсутствующее постановление, постановление без строки в реестре.

Тесты проверяют ожидаемое решение по **каждой** строке, а не итоговые счётчики:
иначе две ошибки в разные стороны компенсируют друг друга и прогон выглядит
зелёным.

## Что нужно согласовать до боевого запуска

1. **Тексты мотивированных суждений** (`spisanie/templates.py`) — рабочая
   заготовка, а не согласованный юридический текст. Их должны утвердить юристы
   и методологи. Вынесены в отдельный файл, чтобы правки не требовали кода.
2. **Формулировки в постановлениях, подтверждающие отсутствие имущества**
   (`NO_PROPERTY_MARKERS` в `spisanie/postanovlenie.py`) — у разных ОСП они
   отличаются. Список нужно дополнить по реальной выборке; пока формулировка не
   распознана, решение будет отрицательным, а не ложно-положительным.
3. **Считать ли п. 3 ч. 1 ст. 46 основанием для списания** — сейчас разрешены
   пп. 3 и 4 (`DOPUSTIMYE_PUNKTY` в `spisanie/st46.py`).
4. **Что делать с дублями** — сейчас все строки дубля уходят на ручное
   рассмотрение.

## Структура

```
run_sid.py              CLI скрипта 1
run_st46.py             CLI скрипта 2
make_test_data.py       генератор вымышленных данных
spisanie/
  common.py             чтение реестра, нормализация, разбор дат, дубли
  sid.py                правило по сроку исковой давности
  st46.py               правило по ст. 46 + сверка ФИО
  postanovlenie.py      чтение и разбор постановления (.pdf/.docx/.txt)
  templates.py          тексты мотивированных суждений
  report.py             запись .xlsx
tests/test_scenarios.py тесты
```
